# UrlShortener — сервис сокращения ссылок

## Описание проекта

UrlShortener — консольное приложение на Java для создания и управления короткими ссылками.

Сервис позволяет сокращать длинные URL, устанавливать ограничения на количество переходов, контролировать срок действия ссылок и управлять ими через консольное меню.

Каждый пользователь идентифицируется с помощью UUID без необходимости регистрации с паролем.

## Возможности приложения

- Создание коротких ссылок.
- Генерация коротких кодов с проверкой уникальности.
- Идентификация пользователей по UUID.
- Создание нескольких ссылок одним пользователем.
- Ограничение количества переходов.
- Автоматическая блокировка после исчерпания лимита.
- Ограничение времени жизни ссылок.
- Автоматическое удаление просроченных ссылок.
- Просмотр собственных ссылок и статистики.
- Изменение лимита переходов.
- Удаление собственных ссылок.
- Защита от изменения и удаления чужих ссылок.
- Открытие исходного адреса в браузере.
- Сохранение данных пользователей в файл.

## Установка и запуск

1. Склонируйте репозиторий:

```bash
git clone https://github.com/Dan12345123452/UrlShortener.git
```

2. Перейдите в папку проекта:

```bash
cd UrlShortener
```

3. Откройте проект в IntelliJ IDEA.

4. Убедитесь, что для проекта выбран JDK 17.

5. Дождитесь загрузки Maven-зависимостей.

6. Откройте файл `Main.java`.

7. Запустите метод `main()`.

При первом запуске программа попросит ввести имя пользователя.

После входа откроется консольное меню приложения.

## Конфигурация

Настройки приложения находятся в файле:

`src/main/resources/application.properties`

Доступные параметры:

| Параметр | Значение по умолчанию | Назначение |
|---|---:|---|
| `link.ttl.hours` | 24 | Время жизни ссылки в часах |
| `link.default.max-clicks` | 10 | Лимит переходов по умолчанию |
| `link.short-code.length` | 7 | Длина короткого кода |
| `link.cleanup.interval.seconds` | 60 | Интервал автоматической очистки |

Параметры можно изменять без внесения изменений в Java-код.

## Архитектура приложения

- **model** — модели пользователей и коротких ссылок.
- **config** — загрузка конфигурации приложения.
- **repository** — хранение, поиск и удаление данных.
- **service** — бизнес-логика приложения.
- **ui** — консольный интерфейс.
- **util** — генерация коротких кодов и проверка URL.


## Назначение Java-классов

### config
- AppConfig — загрузка и хранение настроек приложения.

### model
- User — модель пользователя с UUID и именем.
- ShortLink — модель короткой ссылки, содержащая исходный URL,
  владельца, дату создания, срок действия и счётчик переходов.

### repository
- UserRepository — сохранение и загрузка пользователей из файла.
- LinkRepository — хранение, поиск и удаление коротких ссылок.

### service
- UserService — регистрация и идентификация пользователей.
- LinkService — создание ссылок, учёт переходов,
  изменение лимитов, проверка доступа и очистка.

### ui
- ConsoleMenu — консольное меню и взаимодействие с пользователем.

### util
- CodeGenerator — генерация коротких кодов.
- UrlValidator — проверка корректности исходных URL.

### Главный класс
- Main — создание компонентов приложения, запуск консольного меню
  и планировщика автоматической очистки.

## Хранение данных

UUID и имена пользователей сохраняются в файле `data/users.txt`.

Файл создаётся автоматически при сохранении первого пользователя, если он ещё не существует.

Короткие ссылки и их статистика хранятся в оперативной памяти. После завершения работы приложения они удаляются.

Папка `data` исключена из Git, поэтому локальные данные пользователей не публикуются в репозитории.

Адрес `short.local` используется для отображения коротких ссылок в учебной консольной версии. Публичный HTTP-сервер перенаправления в проекте не реализован.

## Тестирование

В проекте реализовано 44 автоматических теста с использованием JUnit 5.

Для запуска тестов выполните:

```bash
mvn clean test
```

Тесты проверяют:

- создание пользователей и работу UUID;
- создание коротких ссылок;
- подсчёт переходов;
- блокировку после достижения лимита;
- проверку URL;
- разграничение прав пользователей;
- изменение и удаление ссылок;
- хранение и загрузку пользователей;
- автоматическую очистку просроченных ссылок.

### Полная проверка проекта

Для очистки предыдущих результатов сборки, проверки форматирования, компиляции и запуска тестов выполните:

```bash
mvn clean verify
```

Для автоматического форматирования Java-кода используется Spotless:

```bash
mvn spotless:apply
```

## Автоматизация

В проекте настроен GitHub Actions.

При отправке изменений в ветку `main` автоматически выполняются:

- установка JDK 17;
- сборка проекта Maven;
- проверка форматирования Java-кода;
- запуск автоматических тестов.

Workflow находится в `.github/workflows/maven.yml`.
